# contrib_from_differences.py

Вспомогательный скрипт для подготовки плоского списка contrib-расширений из SGML-документации. На вход принимает `differences.sgml`, на выходе — `contrib.txt` рядом со скриптом, по одному имени расширения на строку.

> Это **не** основной `contrib.py` из этой же папки. Логика и формат входа/выхода у скриптов разные — см. `README.md`. Файлы лежат рядом, чтобы удобно было пользоваться обоими в рамках одного цикла подготовки списков contrib-расширений.

## Что именно он извлекает

Из SGML-файла вытаскивается раздел вида

```sgml
<sect2 id="differences-contrib">
  ...
  <para>
    <link linkend="auto_dump">auto_dump</link> — ...
  </para>
  <para>
    <link linkend="credcheck">credcheck</link> — ...
  </para>
  ...
</sect2>
```

В этом разделе ищутся все `<link ... linkend="...">`, и значения атрибута `linkend` собираются в список — с дедупликацией и сохранением порядка первого появления. Если раздела `<sect2 id="differences-contrib">` в файле нет, скрипт сразу падает с понятным сообщением.

Парсинг сделан на регулярных выражениях, без полноценного XML-парсера — это намеренно, чтобы не тащить лишних зависимостей. Поэтому экзотическое форматирование (например, разрыв атрибутов на несколько строк) теоретически может быть упущено; для типового SGML, который лежит в `differences.sgml`, всё работает.

## Требования

- Python 3.6+ (только стандартная библиотека, без сети).

## Входные данные

Источник `differences.sgml` можно указать двумя способами:

1. Локальный файл `differences.sgml` рядом со скриптом — поведение по умолчанию.
2. Произвольный путь к локальному файлу — первым аргументом командной строки или ответом на интерактивный запрос.

`differences.sgml` в репозиторий не выкладывается (см. `.gitignore`) — это пользовательские данные. Положите свой файл рядом со скриптом или передавайте путь в качестве аргумента.

## Выходные данные

Файл `contrib.txt` рядом со скриптом — простой текстовый список имён расширений, по одному в строке, в порядке появления в SGML, без дубликатов:

```
auto_dump
credcheck
dbcopies_decoding
fasttrun
fulleq
hypopg
...
```

В конце файла ставится завершающий `\n`, если список непустой. Имя выходного файла фиксированное — каждый запуск перезаписывает `contrib.txt`.

## Запуск

### Из терминала

Без аргумента — будет интерактивный запрос источника (Enter без ввода → локальный `./differences.sgml`):

```bash
./contrib_from_differences.py
```

С явным аргументом — путь к локальному файлу:

```bash
./contrib_from_differences.py /path/to/differences.sgml
./contrib_from_differences.py ~/Downloads/differences.sgml
```

Скрипт сам переключает рабочий каталог на папку, где он лежит, поэтому его можно вызывать из любой директории — выходной `contrib.txt` всегда создаётся рядом со скриптом.

### Через двойной клик в файловом менеджере

Файл уже настроен под запуск из штатного файлового менеджера Ubuntu (есть shebang `#!/usr/bin/env python3`, бит исполняемости установлен, переводы строк LF). Двойной клик → выбрать `Run in Terminal` (или «Запустить в терминале») — откроется окно, скрипт спросит источник, и после завершения попросит нажать Enter, чтобы окно закрылось.

При запуске без терминала (`Run`) интерактивный запрос показать негде, поэтому будет использован локальный `./differences.sgml`.

## Поведение и ограничения

- Скрипт работает только с локальными файлами и не делает никаких сетевых вызовов.
- При любом исключении (нет файла, отсутствует раздел `differences-contrib`, ошибка прав и т.п.) выводится traceback, и скрипт всё равно ждёт нажатия Enter — ошибку успеешь прочитать.
- Имя выходного файла фиксированное — каждый запуск перезаписывает `contrib.txt`. Если нужно сохранить результаты для разных входов, переименуйте файл вручную перед следующим запуском.
- Дубликаты `linkend` внутри раздела автоматически схлопываются — остаётся первое вхождение.
