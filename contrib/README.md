# contrib.py

Скрипт сверяет версии contrib-компонентов по изданиям продукта.

Для каждого `contrib.json` из списка в скрипте он:

1. Достаёт номер версии из поля `current_version`.
2. Ищет версию документации в `<имя>.sgml` рядом с JSON (каталог `contrib` репозитория).
3. Ищет `default_version` в `.control` того же расширения.
4. Пишет текстовые файлы — отдельный для каждого издания и сводный со всеми уникальными компонентами. В конце каждого файла — сводка: несовпадения версий, расширения без `.control`, без версии в sgml и без файла sgml.

## Требования

- Python 3.6+ (используется только стандартная библиотека). Сеть не нужна.
- Локальные деревья репозиториев: `contrib.json`, каталоги расширений, `*.sgml` и `*.control`.

## Входные данные

Список путей задан в `DEFAULT_CONTRIB_JSON` в начале `contrib.py`. Сейчас это:

- `/home/kot/repo/tantor-db-18_6/tantor/contrib/contrib.json`
- `/home/kot/repo/tantor-db-17_11/tantor/contrib/contrib.json`
- `/home/kot/repo/tantor-db-16_15/tantor/contrib/contrib.json`
- `/home/kot/repo/tantor-db-15_19/tantor/contrib/contrib.json`
- `/home/kot/repo/tantor-db-14_24/tantor/contrib/contrib.json`

Аргументов командной строки нет: чтобы сменить набор источников, правьте этот список. Каждый путь обрабатывается отдельно. Каталог, в котором лежит JSON, считается каталогом `contrib` и обходится в поисках sgml и control.

Метка версии для имён выходных файлов берётся из фрагмента пути `tantor-db-<метка>` (например, `18_6`). Если такого фрагмента нет, используется имя каталога, в котором лежит JSON, либо `unknown`.

Формат JSON:

```json
{
  "contrib": [
    {
      "name": "credcheck",
      "current_version": "https://github.com/MigOpsRepos/credcheck/releases/tag/v4.6",
      "url": "https://github.com/MigOpsRepos/credcheck",
      "editions": ["se", "certified", "certified-2", "se-1c"],
      "skip_log_verify": "0",
      "shared_preload_libraries": "credcheck"
    }
  ]
}
```

Значимые поля:

| Поле              | Назначение                                                                 |
| ----------------- | -------------------------------------------------------------------------- |
| `name`            | Имя компонента. Ключ уникальности в сводном файле и имя каталога расширения. |
| `current_version` | URL на тег/релиз/ветку или голый номер версии (`1.1`, `v1.2.3`).          |
| `editions`        | Издания, в файлы которых попадёт компонент.                                |

Поля `url`, `skip_log_verify` и `shared_preload_libraries` скриптом не используются (но допустимы в JSON).

Издания, которые попадают в отдельные файлы: `be`, `se`, `se-1c`, `certified`, `certified-2`, `free`, `persey`. Значение из `editions`, которого нет в этом списке, в отдельный файл не пишется; в сводный `*_all.txt` компонент всё равно попадает.

Заглушки `"...."`, `"..."` и пустая строка в `current_version` не дают версии из JSON — поля `json=` в строке не будет.

### Версия из `current_version`

Номер ищется по набору регулярных выражений, в том числе:

- голая версия целиком: `1.1`, `v1.2.3`;
- `/releases/tag/v4.6`, `/releases/tag/v1.2.3`, `/releases/tag/ver_1.2.3`;
- `/tag/v1.2`, `/tag/ver_1.2`, `/tag/VERSION_1_2_3`, `/tag/REL2_2_5`, `/tag/wal2json_2_6`;
- `/tree/v1.2.3`, `/tree/ver_1.2.3`, `/tree/1.2.3`;
- `/tag/refs/tags/v1.2.3`, а также голые `/1.2.3/` и `/1.2/` в пути.

Берётся первое совпадение. Подчёркивания в номере (`1_2_3`) заменяются на точки (`1.2.3`). Префикс `v` в номер не входит.

### Версия из sgml

В каталоге расширения `<contrib>/<name>/` читается файл `<name>.sgml` (первые 4096 символов). Ищется строка вида:

```xml
<emphasis role="strong">Version</emphasis> 1.2.3
```

Допустимы пробелы, необязательное двоеточие и любой регистр слова `Version`. Найденный номер попадает в строку как `sgml=`.

Отсутствие файла `<name>.sgml` и отсутствие номера в существующем файле учитываются отдельно (см. сводку в конце выходного файла).

### Версия из control

В том же каталоге расширения ищется `default_version` в файле `<name>.control`. Если его нет, берётся первый по имени `*.control` в корне каталога. Строка вида `default_version = '1.0'` (кавычки одинарные или двойные) попадает в результат как `control=`.

## Выходные данные

Скрипт переходит в свой каталог, поэтому все `*.txt` создаются рядом с `contrib.py`, откуда бы его ни запустили.

Имена файлов: `<метка>_<издание>.txt` и `<метка>_all.txt`. Для дерева `tantor-db-18_6` это `18_6_be.txt`, `18_6_se.txt`, `18_6_se-1c.txt`, `18_6_certified.txt`, `18_6_certified-2.txt`, `18_6_free.txt`, `18_6_persey.txt` и `18_6_all.txt`. Файл издания создаётся даже если в него не попал ни один компонент.

Формат строки компонента (ссылка пишется только если на вопрос при запуске ответили «да»):

```
<name> json=<версия> <current_version_url> sgml=<версия> control=<версия>
```

Любой из фрагментов `json=`, URL, `sgml=` и `control=` опускается, если соответствующего значения нет. Строки внутри файла отсортированы лексикографически по полному тексту строки.

После списка — пустая строка и четыре блока:

- `Не совпадают версии` — либо список таких строк, либо `Все версии совпадают`.
- `Расширения без .control` — либо список строк, либо `Все расширения с .control`.
- `Расширения без версии в sgml` — либо список строк, либо `Все расширения с версиями в sgml`.
- `Расширения без sgml` — имена компонентов без файла `<name>.sgml`, либо `Все расширения с sgml`.

Несовпадением считается любой случай, когда задана хотя бы одна из трёх версий (json, sgml, control) и при этом не все три присутствуют и равны друг другу. Если нет ни одной версии, компонент в этот список не попадает.

В `*_all.txt` компоненты уникальны по `name`: при повторе остаётся последняя запись. В файлах изданий каждая запись из JSON добавляется отдельно.

## Запуск

Один вопрос на весь прогон, затем обрабатываются все пути из `DEFAULT_CONTRIB_JSON`:

```bash
./contrib.py
```

```
Писать полную ссылку current_version? (y/д — да, Enter — нет):
```

Ответ `y`, `yes`, `д`, `да` или `1` добавляет URL в каждую строку. Пустой ввод и конец ввода (нет терминала) оставляют строки без URL.

Файл рассчитан на запуск из файлового менеджера Ubuntu: shebang `#!/usr/bin/env python3`, бит исполняемости, переводы строк LF. Двойной клик → `Run in Terminal` — откроется окно с вопросом про ссылку, и после завершения скрипт попросит нажать Enter.

## Поведение и ограничения

- Скрипт читает только локальные файлы и не ходит в сеть.
- При любой ошибке (нет файла, битый JSON, нет прав) печатается traceback, затем скрипт ждёт Enter. Обработка следующих путей из списка при этом не продолжается.
- Нет файла `<name>.sgml`, нет номера `Version` в нём или нет `default_version` в `.control` — компонент всё равно попадает в списки, а в конце файла оказывается в соответствующей сводке.
- Если ни один шаблон `extract_version` не подошёл, фрагмент `json=` в строку не попадает.
