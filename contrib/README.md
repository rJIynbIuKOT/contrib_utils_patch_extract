# contrib.py

Скрипт для генерации списков contrib-компонентов по изданиям продукта на основе `contrib.json`.

Для каждого компонента из исходного JSON извлекается номер версии из ссылки `current_version`. Затем формируются текстовые файлы — отдельный для каждого издания и сводный со всеми уникальными компонентами.

## Требования

- Python 3.6+ (используется только стандартная библиотека). Сеть не нужна.

## Входные данные

Источник `contrib.json` можно указать двумя способами (см. раздел «Запуск»):

1. Локальный файл `contrib.json` рядом со скриптом — поведение по умолчанию.
2. Произвольный путь к локальному файлу — первым аргументом командной строки или ответом на интерактивный запрос.

Если у вас приватный репозиторий — скачайте `contrib.json` через браузер (страница файла → `Raw` → «Сохранить как…») и передайте скрипту путь к сохранённому файлу.

Формат самого JSON:

```json
{
  "contrib": [
    {
      "name": "credcheck",
      "current_version": "https://github.com/MigOpsRepos/credcheck/releases/tag/v4.6",
      "url": "https://github.com/MigOpsRepos/credcheck",
      "editions": ["se", "certified", "certified-2", "se-1c"],
      "skip_log_verify": "0",
      "shared_preload_libraries": "credcheck"
    }
  ]
}
```

Значимые поля для скрипта:

| Поле              | Назначение                                                                 |
| ----------------- | -------------------------------------------------------------------------- |
| `name`            | Имя компонента (используется как ключ уникальности и попадает в строку).   |
| `current_version` | URL на тег/релиз/ветку — из него вытягивается номер версии.                |
| `editions`        | Список изданий, в файлы которых попадёт компонент.                         |

Поля `url`, `skip_log_verify` и `shared_preload_libraries` скриптом игнорируются (но допустимы в JSON).

Заглушки `"...."` или пустые строки в `current_version` обрабатываются корректно — для таких компонентов версия просто не попадает в итоговую строку.

## Извлечение версии

Из `current_version` вытягиваются номера по набору регулярных выражений, в т. ч.:

- `/releases/tag/v4.6`, `/releases/tag/v1.2.3`
- `/tag/v1.2`, `/tag/VERSION_1_2_3`, `/tag/REL2_2_5`, `/tag/wal2json_2_6`
- `/tree/v1.2.3`, `/tree/ver_1.2.3`, `/tree/1.2.3`
- `/refs/tags/v1.2.3`, а также голые `/1.2.3/` и `/1.2/` в пути.

Подчёркивания в номере версии (например, `1_2_3`) преобразуются в точки (`1.2.3`).

## Выходные данные

Все файлы создаются рядом со скриптом.

- `be.txt`, `se.txt`, `se-1c.txt`, `certified.txt`, `certified-2.txt`, `free.txt` — по одному файлу на издание, содержат строки только тех компонентов, в `editions` которых упомянуто это издание.
- `all.txt` — сводный список всех уникальных компонентов (по `name`).

Формат строки в файле:

```
<name> <version> <current_version_url>   # если версию удалось извлечь
<name> <current_version_url>             # если версию извлечь не удалось
```

Внутри каждого файла строки отсортированы лексикографически.

## Запуск

### Из терминала

Без аргумента — будет интерактивный запрос источника (Enter без ввода → локальный `./contrib.json`):

```bash
./contrib.py
```

С явным аргументом — путь к локальному файлу:

```bash
./contrib.py /path/to/contrib.json
./contrib.py ~/Downloads/contrib.json
```

Скрипт сам переключает рабочий каталог на папку, где он лежит, поэтому его можно вызывать из любой директории — выходные `*.txt` всегда создаются рядом со скриптом.

### Через двойной клик в файловом менеджере

Файл уже настроен под запуск из штатного файлового менеджера Ubuntu (есть shebang `#!/usr/bin/env python3`, бит исполняемости установлен, переводы строк LF). Двойной клик → выбрать `Run in Terminal` (или «Запустить в терминале») — откроется окно, скрипт спросит источник, и после завершения попросит нажать Enter, чтобы окно закрылось.

При запуске без терминала (`Run`) интерактивный запрос показать негде, поэтому будет использован локальный `./contrib.json`.

## Поведение и ограничения

- Скрипт работает только с локальными файлами и не делает никаких сетевых вызовов.
- При любом исключении (нет файла, битый JSON, ошибка прав и т.п.) выводится traceback, и скрипт всё равно ждёт нажатия Enter — ошибку успеешь прочитать.
- Дубликаты компонентов с одинаковым `name` в `all.txt` схлопываются — остаётся последний встретившийся.
- Если ни один из шаблонов в `extract_version` не подошёл, в строку попадает только имя и исходный URL.
