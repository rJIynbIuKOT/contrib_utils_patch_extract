# compare_with_differences.py

Скрипт сверяет список contrib-расширений из SGML-документации (`differences_*.sgml`) со списками, которые ранее собрал `contrib.py` из `contrib.json`. Для каждого издания пишет файл `contrib_<версия>_<издание>.txt`: сначала расширения из differences, затем расхождения с `contrib.json`.

> Это **не** основной `contrib.py` из этой же папки. Типовой цикл: сначала `contrib.py` (получаются `18_6_be.txt` и т.п.), затем `compare_with_differences.py`.

## Что именно он извлекает

Из каждого SGML-файла вытаскивается раздел вида

```sgml
<sect2 id="differences-contrib">
  ...
  <para>
    <link linkend="auto_dump">auto_dump</link> — ...
  </para>
  <para>
    <link linkend="credcheck">credcheck</link> — ...
  </para>
  ...
</sect2>
```

В этом разделе ищутся все `<link ... linkend="...">`, и значения атрибута `linkend` собираются в список — с дедупликацией и сохранением порядка первого появления. Если раздела `<sect2 id="differences-contrib">` в файле нет, скрипт сразу падает с понятным сообщением.

Парсинг сделан на регулярных выражениях, без полноценного XML-парсера — это намеренно, чтобы не тащить лишних зависимостей.

## Издания

Обрабатываются только пять изданий:

| Издание       | Файл differences                                                                 |
| ------------- | -------------------------------------------------------------------------------- |
| `be`          | `/home/kot/repo/tantor-db-18_6/tantor/doc/new_pages/differences_be_18_6.sgml`     |
| `se`          | `/home/kot/repo/tantor-db-18_6/tantor/doc/new_pages/differences_se_18_6.sgml`     |
| `se-1c`       | `/home/kot/repo/tantor-db-18_6/tantor/doc/new_pages/differences_se1c_18_6.sgml`   |
| `certified`   | `/home/kot/repo/tantor-db-18_6/tantor/doc/new_pages/differences_certified_18_6.sgml` |
| `certified-2` | `/home/kot/repo/tantor-db-18_6/tantor/doc/new_pages/differences_certified_2_18_6.sgml` |

Пути зашиты в `DEFAULT_DIFFERENCES` внутри скрипта — так же, как `contrib.py` хранит пути к `contrib.json`. Метка версии (`18_6`) берётся из сегмента `tantor-db-18_6` в пути.

`free` не обрабатывается.

## Требования

- Python 3.6+ (только стандартная библиотека, без сети).
- Рядом со скриптом уже должны лежать файлы `contrib.py` для той же версии и изданий: `18_6_be.txt`, `18_6_se.txt`, `18_6_se-1c.txt`, `18_6_certified.txt`, `18_6_certified-2.txt`. Из каждого берётся только первая секция (до пустой строки), имя расширения — первое слово строки.

## Выходные данные

Все файлы создаются рядом со скриптом:

- `contrib_18_6_be.txt`
- `contrib_18_6_se.txt`
- `contrib_18_6_se-1c.txt`
- `contrib_18_6_certified.txt`
- `contrib_18_6_certified-2.txt`

Структура каждого файла:

```
page_repair
pg_background
...

Расширения есть в contrib.json, но нет differences:
wal2json

Расширения есть в differences, но нет contrib.json:
```

Первый блок — имена из differences, в порядке появления в SGML, без дубликатов. Дальше два блока расхождений. Если расхождений нет, заголовок всё равно пишется, список под ним пустой.

В списке из differences остаётся имя как в SGML (`oauth-validator`). При сверке `oauth-validator` считается тем же расширением, что `oauth_base_validator` в `contrib.json` (алиас в `NAME_ALIASES`).

## Запуск

Аргументы не нужны — скрипт сам обходит зашитый список путей:

```bash
./compare_with_differences.py
```

Скрипт сам переключает рабочий каталог на папку, где он лежит, поэтому его можно вызывать из любой директории — выходные `contrib_18_6_*.txt` всегда создаются рядом со скриптом.

### Через двойной клик в файловом менеджере

Файл уже настроен под запуск из штатного файлового менеджера Ubuntu (есть shebang `#!/usr/bin/env python3`, бит исполняемости установлен, переводы строк LF). Двойной клик → выбрать `Run in Terminal` (или «Запустить в терминале») — откроется окно, скрипт обработает все пять изданий и после завершения попросит нажать Enter, чтобы окно закрылось.

## Поведение и ограничения

- Скрипт работает только с локальными файлами и не делает никаких сетевых вызовов.
- При любом исключении (нет SGML, нет `18_6_<издание>.txt`, отсутствует раздел `differences-contrib`, ошибка прав и т.п.) выводится traceback, и скрипт всё равно ждёт нажатия Enter — ошибку успеешь прочитать.
- Дубликаты `linkend` внутри раздела автоматически схлопываются — остаётся первое вхождение.
- Каждый запуск перезаписывает `contrib_18_6_*.txt`.
