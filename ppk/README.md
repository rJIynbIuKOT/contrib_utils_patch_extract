# ppk.py

Скрипт для извлечения плоского списка компонентов ППК (программно-программный комплекс) из CycloneDX-совместимого SBOM-JSON в формат «`name version vcs_url`», по одной строке на компонент.

## Требования

- Python 3.6+ (используется только стандартная библиотека). Сеть не нужна.

## Входные данные

Источник JSON указывается двумя способами (см. раздел «Запуск»):

1. Локальный файл `ppk.json` рядом со скриптом — поведение по умолчанию.
2. Произвольный путь к локальному файлу — первым аргументом командной строки или ответом на интерактивный запрос. Имя на практике обычно содержит версию Tantor, например `ППК_Tantor_16.8.json`.

Формат самого JSON — [CycloneDX](https://cyclonedx.org/) (специфическая версия не важна, читаются только нужные поля):

```json
{
  "bomFormat": "CycloneDX",
  "specVersion": "1.6",
  "components": [
    {
      "type": "library",
      "name": "ansible",
      "version": "2.17.7",
      "externalReferences": [
        { "type": "vcs", "url": "https://github.com/ansible/ansible/tree/v2.17.7" }
      ]
    }
  ]
}
```

Значимые поля для скрипта:

| Поле                            | Назначение                                                                       |
| ------------------------------- | -------------------------------------------------------------------------------- |
| `components[].name`             | Имя компонента — первое поле строки.                                             |
| `components[].version`          | Версия компонента — второе поле строки (берётся как есть, без парсинга).         |
| `components[].externalReferences[]` | Берётся первая запись с `type == "vcs"` — её `url` идёт третьим полем строки. |

Остальные поля (`type`, `properties`, `manufacturer` и т.п.) скриптом игнорируются (но допустимы в JSON).

Если у компонента нет `vcs`-ссылки, в строку попадает только `name` и `version` (без хвостового пробела).

## Выходные данные

Один текстовый файл рядом со скриптом, имя — производное от имени входа (`<stem>.json` → `<stem>.txt`):

- `ppk.json` → `ppk.txt`
- `ППК_Tantor_16.8.json` → `ППК_Tantor_16.8.txt`
- `/path/to/ppk_17_5.json` → `/path/to/ppk_17_5.txt`

Формат строки:

```
<name> <version> <vcs_url>
```

Порядок строк — как в исходном `components` (без сортировки).

## Запуск

### Из терминала

Без аргумента — будет интерактивный запрос источника (Enter без ввода → локальный `./ppk.json`):

```bash
./ppk.py
```

С явным аргументом — путь к локальному файлу:

```bash
./ppk.py ППК_Tantor_16.8.json
./ppk.py ~/Downloads/ППК_Tantor_17.5.json
```

Скрипт сам переключает рабочий каталог на папку, где он лежит, поэтому его можно вызывать из любой директории; выходной `*.txt` создаётся **рядом со входным файлом** (а если путь относительный — в папке скрипта).

### Через двойной клик в файловом менеджере

Файл уже настроен под запуск из штатного файлового менеджера Ubuntu (есть shebang `#!/usr/bin/env python3`, бит исполняемости установлен, переводы строк LF). Двойной клик → выбрать `Run in Terminal` (или «Запустить в терминале») — откроется окно, скрипт спросит источник, и после завершения попросит нажать Enter, чтобы окно закрылось.

При запуске без терминала (`Run`) интерактивный запрос показать негде, поэтому будет использован локальный `./ppk.json` (если его нет — будет ошибка, видимая только в логах сессии).

## Поведение и ограничения

- Скрипт работает только с локальными файлами и не делает никаких сетевых вызовов.
- При любом исключении (нет файла, битый JSON, отсутствует ключ `components` и т.п.) выводится traceback, и скрипт всё равно ждёт нажатия Enter — ошибку успеешь прочитать.
- Если у компонента несколько записей в `externalReferences`, берётся **первая** с `type == "vcs"`; остальные игнорируются.
- Дубликаты по `name` не схлопываются — если в исходнике два компонента с одинаковым именем, в выходном файле будут две строки.
