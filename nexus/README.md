# nexus.py

Скрипт для генерации компактного отчёта по компонентам сборки из `nexus.json`: имя, версия, git-URL и SHA коммита. Результат пишется в `nexus.txt` рядом со скриптом — этот файл удобно прикладывать к материалам о составе сборки (Nexus / артефакты).

## Требования

- Python 3.6+ (используется только стандартная библиотека). Сеть не нужна.

## Входные данные

Источник `nexus.json` можно указать двумя способами (см. раздел «Запуск»):

1. Локальный файл `nexus.json` рядом со скриптом — поведение по умолчанию.
2. Произвольный путь к локальному файлу — первым аргументом командной строки или ответом на интерактивный запрос.

Если у вас приватный репозиторий — скачайте `nexus.json` через браузер (страница файла → `Raw` → «Сохранить как…») и передайте скрипту путь к сохранённому файлу.

Формат самого JSON (на верхнем уровне ожидается ключ `components`; читаются только указанные поля внутри каждого компонента):

```json
{
  "build_id": "...",
  "platform_id": "...",
  "components": {
    "pg_integrity_verifier": {
      "version": "1.1.0",
      "git": {
        "url": "ssh://git@gitlab.example.com/database/pg_integrity_verifier.git",
        "commit_sha": "b210e13cf999b01b22b5a034d544dc4487d88930"
      }
    }
  }
}
```

Значимые поля для скрипта:

| Поле                | Назначение                                               |
| ------------------- | -------------------------------------------------------- |
| `components`        | Словарь компонентов сборки (обязательный ключ).          |
| `<name>.version`    | Номер версии (выводится как есть, без преобразований).   |
| `<name>.git.url`    | URL git-репозитория.                                     |
| `<name>.git.commit_sha` | Полный SHA коммита, на котором собиралась версия.    |

В отличие от `fstek/fstek.py`, поля `version` и `git` лежат **прямо** в компоненте — без вложения в `general`. Поля верхнего уровня (`build_id`, `platform_id` и т.п.) скриптом не используются. Если на верхнем уровне нет ключа `components`, скрипт сразу падает с понятным сообщением.

## Выходные данные

Файл `nexus.txt` рядом со скриптом. По одной строке на компонент в формате:

```
<name> <version> <git_url> <commit_sha>
```

Поля разделяются одним пробелом. Пустые значения (например, отсутствующий `commit_sha`) просто опускаются, лишние пробелы по краям обрезаются. Строки отсортированы по `name` лексикографически.

Пример (фрагмент `nexus.txt`):

```
ansible 2.17.7 https://github.com/ansible/ansible.git dc0e3bd16cc7ded081bc46c88e4e3d1997ca9bb0
ldap2pg 6.3 https://github.com/dalibo/ldap2pg.git b0c6b313b1aa9c640a74a73a00453f7fe4eb32f7
pg_integrity_verifier 1.1.0 ssh://git@gitlab.example.com/database/pg_integrity_verifier.git b210e13cf999b01b22b5a034d544dc4487d88930
```

Имя выходного файла фиксированное (`nexus.txt`). Если нужно сохранить результаты для разных входов (например, для уровней C1 и C2), переименуйте полученный `nexus.txt` после запуска — например, в `nexusC1.txt` / `nexusC2.txt`.

## Запуск

### Из терминала

Без аргумента — будет интерактивный запрос источника (Enter без ввода → локальный `./nexus.json`):

```bash
./nexus.py
```

С явным аргументом — путь к локальному файлу:

```bash
./nexus.py /path/to/nexus.json
./nexus.py ~/Downloads/nexusC1.json
```

Скрипт сам переключает рабочий каталог на папку, где он лежит, поэтому его можно вызывать из любой директории — выходной `nexus.txt` всегда создаётся рядом со скриптом.

### Через двойной клик в файловом менеджере

Файл уже настроен под запуск из штатного файлового менеджера Ubuntu (есть shebang `#!/usr/bin/env python3`, бит исполняемости установлен, переводы строк LF). Двойной клик → выбрать `Run in Terminal` (или «Запустить в терминале») — откроется окно, скрипт спросит источник, и после завершения попросит нажать Enter, чтобы окно закрылось.

При запуске без терминала (`Run`) интерактивный запрос показать негде, поэтому будет использован локальный `./nexus.json`.

## Поведение и ограничения

- Скрипт работает только с локальными файлами и не делает никаких сетевых вызовов.
- При любом исключении (нет файла, битый JSON, отсутствует `components`, ошибка прав и т.п.) выводится traceback, и скрипт всё равно ждёт нажатия Enter — ошибку успеешь прочитать.
- Имя выходного файла фиксированное — каждый запуск перезаписывает `nexus.txt`. Если нужны несколько отчётов, переименуйте файл вручную перед следующим запуском.
- Дубликаты компонентов невозможны: ключи внутри `components` и так уникальны.
