# utils.py

Скрипт для генерации списков утилит по изданиям продукта из двух источников — `utils.json` и `conf.json` — и автоматического сравнения результатов.

Создаёт два файла, которые **должны быть идентичны**: один сгенерирован из `utils.json` (декларации утилит со списком изданий), второй — из `conf.json` (фактическое включение утилит в каждое издание). Любое расхождение явно сигнализируется в выводе.

## Требования

- Python 3.6+ (используется только стандартная библиотека). Сеть не нужна.

## Входные данные

Скрипту нужны два JSON-файла. Их расположение задаётся одним позиционным аргументом, который принимает четыре формы:

| Аргумент                                         | Откуда берутся файлы                                                                                          |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| _пусто_ (Enter)                                  | `./utils.json` и `./conf.json` рядом со скриптом.                                                             |
| Путь к директории                                | `<dir>/utils.json` и `<dir>/conf.json`.                                                                       |
| Путь к `utils.json` (любое имя, оканчивается на `.json`) | `conf.json` ищется в той же папке. Исключение: если `utils.json` лежит в подпапке `contrib/`, то `conf.json` берётся **на уровень выше**. |
| Строка-версия (без `/` и без `.json`), напр. `17_7` | `/home/kot/repo/tantor-db-<version>/tantor/contrib/utils.json` и `/home/kot/repo/tantor-db-<version>/tantor/conf.json`. |

Базовый шаблон для версии задан константой `VERSION_BASE_TEMPLATE` в начале скрипта — его легко заменить под другое расположение локальных репозиториев.

Если в интерактивном режиме скрипт после первого ответа не нашёл `utils.json` или `conf.json` по вычисленному пути, он отдельно спросит путь именно к этому файлу:

```
Файл conf.json не найден.
Путь до conf.json (Enter — оставить как есть):
```

Аналогично — для `utils.json`, если он не нашёлся. Это удобно, когда `conf.json` лежит в другом каталоге, чем `utils.json` (например, у вас собственная раскладка проекта). При запуске с CLI-аргументом такие переспросы **не** делаются — это поведение оставлено для автоматизации.

### Формат `utils.json`

```json
{
  "utility_tools": [
    {
      "name": "data_generator",
      "editions": ["be", "se", "se-1c", "certified", "certified-2"]
    }
  ]
}
```

Учитываются только издания из набора `be`, `se`, `se-1c`, `certified`, `certified-2` (на выходе `se-1c` → `se1c`, `certified-2` → `certified_2`).

### Формат `conf.json`

```json
{
  "editions": {
    "be":          { "utils": { "data_generator": { /* ... */ } } },
    "se":          { "utils": { /* ... */ } },
    "se1c":        { "utils": { /* ... */ } },
    "certified":   { "utils": { /* ... */ } },
    "certified_2": { "utils": { /* ... */ } }
  }
}
```

Из `editions[<ed>].utils` берутся только **ключи** — список названий утилит.

## Выходные данные

Оба файла создаются **рядом со скриптом** независимо от того, откуда взяты входные JSON:

- `utils.txt` — на основе `utils.json`.
- `utils_conf.txt` — на основе `conf.json`.

Структура файла:

```
be
data_generator
pg_diag_setup
...

se
columnar_migrator
data_generator
...

(...)

certified_2
...

<пустая строка>
data_generator all
columnar_migrator se,se1c,certified,certified_2
```

В верхней части — по разделу на каждое издание (порядок: `be`, `se`, `se1c`, `certified`, `certified_2`), внутри раздела утилиты отсортированы. После всех разделов идёт сводка: для каждой утилиты указано, в каких изданиях она есть, или `all`, если во всех пяти.

После записи скрипт сравнивает оба файла и пишет одну из строк:

- `Файлы utils.txt и utils_conf.txt идентичны.`
- `Обнаружены отличия между utils.txt и utils_conf.txt.`

## Запуск

### Из терминала

Без аргумента — будет интерактивный запрос источника (Enter без ввода → локальные `./utils.json` и `./conf.json`):

```bash
./utils.py
```

С путём к папке или к `utils.json`:

```bash
./utils.py /path/to/tantor-folder
./utils.py /path/to/tantor-folder/contrib/utils.json
./utils.py ~/Downloads/tantor_17_5
```

Со строкой-версией (использует шаблон `/home/kot/repo/tantor-db-<version>/tantor`):

```bash
./utils.py 17_7
./utils.py 16_8
```

Скрипт сам переключает рабочий каталог на папку, где он лежит, поэтому вызов из любой директории корректен; выходные `utils.txt` и `utils_conf.txt` всегда создаются рядом со скриптом.

### Через двойной клик в файловом менеджере

Файл уже настроен под запуск из штатного файлового менеджера Ubuntu (есть shebang `#!/usr/bin/env python3`, бит исполняемости установлен, переводы строк LF). Двойной клик → `Run in Terminal` (или «Запустить в терминале») — откроется окно, скрипт спросит источник, и после завершения попросит нажать Enter, чтобы окно закрылось.

При запуске без терминала (`Run`) интерактивный запрос показать негде, поэтому будут использованы локальные `./utils.json` и `./conf.json` (если их рядом нет — возникнет видимая в логах ошибка).

## Поведение и ограничения

- Скрипт работает только с локальными файлами и не делает никаких сетевых вызовов.
- При любом исключении (нет файла, битый JSON, неподходящий аргумент и т.п.) выводится traceback, и скрипт всё равно ждёт нажатия Enter — ошибку успеешь прочитать.
- Если в `conf.json` нет одного из ожидаемых изданий, его раздел в `utils_conf.txt` будет пустым — это **штатное** поведение.
- Издание `se-1c` в `utils.json` и `se1c` в `conf.json` считаются одним и тем же.
- Шаблон версионного режима (`/home/kot/repo/tantor-db-<v>/tantor`) — пользовательская конкретика. Если у вас другое расположение репозиториев, исправьте константу `VERSION_BASE_TEMPLATE` в начале скрипта или передавайте путь явно.
