# fstek.py

Скрипт для генерации компактного отчёта по компонентам из `config.json`: имя, версия, git-URL и SHA коммита. Результат пишется в `config.txt` рядом со скриптом — этот файл удобно прикладывать к материалам для ФСТЭК.

## Требования

- Python 3.6+ (используется только стандартная библиотека). Сеть не нужна.

## Входные данные

Источник `config.json` можно указать двумя способами (см. раздел «Запуск»):

1. Локальный файл `config.json` рядом со скриптом — поведение по умолчанию.
2. Произвольный путь к локальному файлу — первым аргументом командной строки или ответом на интерактивный запрос.

Если у вас приватный репозиторий — скачайте `config.json` через браузер (страница файла → `Raw` → «Сохранить как…») и передайте скрипту путь к сохранённому файлу.

Формат самого JSON (на верхнем уровне — словарь компонентов; читаются только указанные поля внутри `general`):

```json
{
  "ldap2pg": {
    "general": {
      "version": "6.3",
      "git": {
        "url": "https://github.com/dalibo/ldap2pg.git",
        "commit_sha": "b0c6b313b1aa9c640a74a73a00453f7fe4eb32f7"
      }
    }
  }
}
```

Значимые поля для скрипта:

| Поле                     | Назначение                                               |
| ------------------------ | -------------------------------------------------------- |
| `general.version`        | Номер версии (выводится как есть, без преобразований).   |
| `general.git.url`        | URL git-репозитория.                                     |
| `general.git.commit_sha` | Полный SHA коммита, на котором собиралась версия.        |

В отличие от `contrib_ext_programs/ext.py`, здесь **обрабатываются все ключи верхнего уровня** — никакого фильтр-списка нет. Любые другие поля внутри сущности просто игнорируются.

## Выходные данные

Файл `config.txt` рядом со скриптом. По одной строке на компонент в формате:

```
<name> <version> <git_url> <commit_sha>
```

Поля разделяются одним пробелом. Пустые значения (например, отсутствующий `commit_sha`) просто опускаются, лишние пробелы по краям обрезаются. Строки отсортированы по `name` лексикографически.

Пример (фрагмент `config.txt`):

```
ansible 2.17.7 https://github.com/ansible/ansible.git dc0e3bd16cc7ded081bc46c88e4e3d1997ca9bb0
ldap2pg 6.3 https://github.com/dalibo/ldap2pg.git b0c6b313b1aa9c640a74a73a00453f7fe4eb32f7
pgbouncer 1.24.0 https://github.com/pgbouncer/pgbouncer.git 127bd618503fdb9348e0f3e07b6eb039f40fea16
```

Имя выходного файла фиксированное (`config.txt`). Если нужно сохранить результаты для разных входов (например, для уровней C1 и C2), переименуйте полученный `config.txt` после запуска — например, в `configC1.txt` / `configC2.txt`.

## Запуск

### Из терминала

Без аргумента — будет интерактивный запрос источника (Enter без ввода → локальный `./config.json`):

```bash
./fstek.py
```

С явным аргументом — путь к локальному файлу:

```bash
./fstek.py /path/to/config.json
./fstek.py ~/Downloads/configC1.json
```

Скрипт сам переключает рабочий каталог на папку, где он лежит, поэтому его можно вызывать из любой директории — выходной `config.txt` всегда создаётся рядом со скриптом.

### Через двойной клик в файловом менеджере

Файл уже настроен под запуск из штатного файлового менеджера Ubuntu (есть shebang `#!/usr/bin/env python3`, бит исполняемости установлен, переводы строк LF). Двойной клик → выбрать `Run in Terminal` (или «Запустить в терминале») — откроется окно, скрипт спросит источник, и после завершения попросит нажать Enter, чтобы окно закрылось.

При запуске без терминала (`Run`) интерактивный запрос показать негде, поэтому будет использован локальный `./config.json`.

## Поведение и ограничения

- Скрипт работает только с локальными файлами и не делает никаких сетевых вызовов.
- При любом исключении (нет файла, битый JSON, ошибка прав и т.п.) выводится traceback, и скрипт всё равно ждёт нажатия Enter — ошибку успеешь прочитать.
- Имя выходного файла фиксированное — каждый запуск перезаписывает `config.txt`. Если нужны несколько отчётов, переименуйте файл вручную перед следующим запуском.
- Дубликаты компонентов невозможны: ключи верхнего уровня в JSON и так уникальны.
