# export_patches_csv.py

Скрипт для построения CSV-матрицы «patch × edition» из `conf.json`. По блоку `editions[<ed>].patches` показывает, в какие издания продукта входит каждый патч.

## Требования

- Python 3.6+ (используется только стандартная библиотека). Сеть не нужна.

## Входные данные

Источник `conf.json` указывается двумя способами (см. раздел «Запуск»):

1. Локальный файл `conf.json` рядом со скриптом — поведение по умолчанию.
2. Произвольный путь к локальному файлу — первым аргументом командной строки или ответом на интерактивный запрос (поддерживается `~` для домашнего каталога).

Скрипт ожидает в корне JSON ключ `editions` со словарём, в котором перечислены все издания **из фиксированного списка**: `be`, `se`, `se1c`, `certified`, `certified_2`, `free`. Если хотя бы одного из них нет — будет ошибка.

```json
{
  "editions": {
    "be":          { "patches": ["fix/common", "perf/io"] },
    "se":          { "patches": ["fix/common", "func/1c"] },
    "se1c":        { "patches": ["func/1c"] },
    "certified":   { "patches": ["fix/common"] },
    "certified_2": { "patches": [] },
    "free":        { "patches": ["fix/common"] }
  }
}
```

Значимые поля:

| Поле                                   | Назначение                                                              |
| -------------------------------------- | ----------------------------------------------------------------------- |
| `editions.<edition>.patches`           | Список идентификаторов патчей, входящих в издание (любой строковой тип). |

Остальные поля `conf.json` (`utils`, `extensions`, и т.п.) скриптом игнорируются.

## Выходные данные

Один CSV-файл рядом со скриптом — `pathes.csv` (название историческое; именно с такой опечаткой). Кодировка UTF-8, разделитель — запятая, переводы строк CRLF (стандарт `csv` для Excel-совместимости).

Структура:

```
patch,be,se,se1c,certified,certified_2,free
fix/common,y,y,y,y,y,y
func/1c,,y,y,y,,
func/autonomous_tx,,y,,y,,
...
```

- В шапке после `patch` идут **6 колонок** в фиксированном порядке: `be, se, se1c, certified, certified_2, free`.
- В каждой строке — имя патча и метки `y` в тех колонках, где патч присутствует в `editions[<ed>].patches` (в остальных — пусто).
- Имена патчей в строках отсортированы лексикографически и являются объединением всех `patches` по всем изданиям.

## Запуск

### Из терминала

Без аргумента — будет интерактивный запрос источника (Enter без ввода → локальный `./conf.json`):

```bash
./export_patches_csv.py
```

С явным аргументом — путь к локальному файлу:

```bash
./export_patches_csv.py /path/to/conf.json
./export_patches_csv.py ~/repo/tantor-db-17_7/tantor/conf.json
./export_patches_csv.py ../patch_to_core_improvements/conf.json
```

Скрипт сам переключает рабочий каталог на папку, где он лежит, поэтому его можно вызывать из любой директории; выходной `pathes.csv` всегда создаётся **рядом со скриптом**.

### Через двойной клик в файловом менеджере

Файл уже настроен под запуск из штатного файлового менеджера Ubuntu (есть shebang `#!/usr/bin/env python3`, бит исполняемости установлен, переводы строк LF). Двойной клик → `Run in Terminal` (или «Запустить в терминале») — откроется окно, скрипт спросит источник, и после завершения попросит нажать Enter, чтобы окно закрылось.

При запуске без терминала (`Run`) интерактивный запрос показать негде, поэтому будет использован локальный `./conf.json`.

## Поведение и ограничения

- Скрипт работает только с локальными файлами и не делает никаких сетевых вызовов.
- При любом исключении (нет файла, битый JSON, неполный набор изданий и т.п.) выводится traceback, и скрипт всё равно ждёт нажатия Enter — ошибку успеешь прочитать.
- Список изданий **жёстко зашит** в код константой `EDITION_ORDER`. Если в продукте появилось новое издание (например, `certified_3`), его нужно добавить в эту константу — иначе оно не попадёт в CSV (а если его нет в `conf.json`, при обработке возникнет ошибка о отсутствующем издании).
- Дубликаты в `editions[<ed>].patches` схлопываются (внутри множества).
- Имя выходного файла — `pathes.csv` (с исторической опечаткой). Если нужно другое имя, поменяйте константу `OUTPUT_FILE` в начале скрипта.
